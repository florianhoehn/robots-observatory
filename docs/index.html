    Does the answer change by who asks

    Almost never, and the number that says otherwise is wrong

    We asked every site twice: once as a crawler that says what it is, once as something shaped like a browser. Three different things can show up in the answer, and they are easy to confuse with each other.

    1. … of sites sent back different bytes. Almost none of it is real. Most are two error pages or two cookie banners, identical except for a one-off token stamped into each copy, the same difference you would get loading any page twice yourself.
    2. Read the rules properly and … sites genuinely serve different policy to the two. telegraph.co.uk gives the declared crawler 3,228 bytes of rules and the browser 914. messenger.com does the reverse, handing the browser more than the crawler.
    3. A further … let one identity in and refused the other. That is different access, not different policy, so it is counted separately.

    The first number stays on the page because deleting it would hide how easily a non-finding gets reported as a finding. We publish it so you can see the distance between it and the real one.

    Honesty

    What this cannot tell you

    It can

    • Say what share names AI crawlers, and which ones
    • Say what share publishes a guide, an opt-out or a reservation
    • Say what share asks for money
    • Say whether the answer changes by who asks
    • Show how much of a popularity list is not a website

    It cannot

    • Say whether any of it is enforced. Declared and enforced are different datasets; this is the first
    • Say whether signing your requests helps: nothing was fetched that could be refused
    • Say anything about change over time, yet
    • Speak for other countries: one vantage, one connection
    • Speak for the long tail outside a popularity list
    • Speak for ad technology, 418 domains of which this connection cannot resolve
    • Be read as a floor rather than a count where a host timed out, errored, or answered everything with one stock page

    Method

    How the panel was built

    Tranco list 467YX, 18 October 2026, top 20,000. Nothing was screened by hand: every domain that resolves to a server is in, whether or not it is a website anyone reads. That is the opposite of the smaller panel above, and deliberately so. Hand-screening is a judgement, and a judgement applied 20,000 times is a thumb on the scale.

    3,686 domains were dropped before probing, each for a stated reason: 3,190 have no address record at all and serve nothing from any vantage, 78 more fail to resolve or resolve ambiguously, and 418 are unreachable from this particular connection, which filters ad and tracker domains at the DNS layer. That last group is a fact about the measuring machine rather than the web, so it is published per host instead of quietly absorbed. Every exclusion is one row you can disagree with.

    This run is marked degraded, and the figures are reported anyway. … of hosts returned at least one transport error, mostly TLS failures and connect timeouts, which is what the long tail of a popularity list actually looks like from one home connection. A further … hit the two-minute per-host budget, so their later paths are unmeasured rather than absent, and … answer several paths with one stock body and are discounted rather than counted as publishers. Each of those is a reason a share here reads low, never high.

    Presence is not stance, and a 200 is not a file. A path defined to carry JSON is only counted when its body parses as JSON: seven hosts answered five agent-discovery paths each with a firewall block page carrying a detection timestamp, which defeats both an HTML check and the duplicate-body check, because every copy hashed differently. A zero-length body is not counted either: 36 sites served an empty ads.txt. And a tdmrep.json is read before it is filed as a refusal, because the format expresses permission as readily as reservation. Applying all three cut the agent-card count by a third and the legacy path by nearly half.

    No page was ever fetched. Only files the web publishes for machines to read, so no request was one a site asked crawlers not to make. Twelve requests per site, 1.5 seconds apart. Four of the twelve are controls (security.txt, ads.txt, gpc.json and humans.txt), so the AI-specific numbers can be read against a site's general habit of publishing machine-readable files at all. That claim is checkable from two readable source files rather than merely asserted.

    No model sits in the measurement path. Fetch, parse and count are deterministic, because the output of this project is the difference between runs, and a model that answered slightly differently each week would look exactly like the web changing its mind.
